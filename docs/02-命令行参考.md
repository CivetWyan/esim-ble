# 02 命令行参考

## 调用方式

```sh
.venv/bin/python -m esimble [-v] <命令组> <动作> [参数]
# 用 pip install -e . 安装后也可以：
.venv/bin/esimble [-v] <命令组> <动作> [参数]
```

- `-v` / `--verbose`：输出调试日志，包括每条 APDU 的收发（`apdu >> …` / `apdu << …`）和 bleak 的蓝牙细节。
- 日志会同时写到终端和 `logs/esimble.log`。
- 退出码：0 表示成功；1 表示操作被取消或卡返回非 0 结果；出错时会打印 Python 异常。

命令组：

| 命令组 | 作用 |
|---|---|
| `config` | 查看和修改本地配置 |
| `card` | 通过蓝牙管理 9eSIM 卡上的号码 |
| `mifi` | 随身 WiFi 的状态、短信和设备控制 |

## config

```sh
esimble config [--ble-device NAME] [--ble-password] [--mifi-host IP] [--mifi-password] [--secure-tls]
```

| 参数 | 说明 |
|---|---|
| `--ble-device NAME` | 卡的蓝牙名 |
| `--ble-password` | 交互输入卡的管理密码；直接回车表示用设备默认密码 |
| `--mifi-host IP` | 随身 WiFi 管理地址 |
| `--mifi-password` | 交互输入随身 WiFi 管理密码 |
| `--secure-tls` | 装卡时校验 SM-DP+ 的 TLS 证书（默认跳过，原因见 01 文档第 5 节） |

不带参数运行时只显示配置。输出示例：

```json
{
  "ble_device": "9eSIM000000",
  "mifi_host": "192.168.0.1",
  "mifi_password_set": true,
  "insecure_tls": true
}
```

## card：卡管理（蓝牙）

每条 `card` 命令的过程都一样：
1. 扫描找到卡；
2. 连接并登录，确认卡处于 eUICC 模式；
3. 打开 ISD-R 逻辑通道；
4. 执行操作；
5. 断开蓝牙。

一条命令通常要 5～10 秒，装卡要 40 秒以上。连接失败会自动重试一次；如果卡返回"正在切换配置"（6999/6985），会等 20 秒再重试一次。

### card list

```sh
esimble card list
```

读取 EID、剩余存储空间和号码列表，并同步到本地数据库。

输出示例：

```
EID: 89086030****************
free NVM: 1047.58 KB
   8999500000000000022    disabled  Cellfie / Cellfie GE 2  [GE-Cellfie]
 * 89852000000000000011   enabled   Saily / WEBBING
```

列说明：

| 列 | 含义 |
|---|---|
| `*` | 当前启用的号码 |
| ICCID | 号码的卡号 |
| 状态 | `enabled` 或 `disabled` |
| 运营商 / 名称 | 配置里写的运营商和配置名 |
| `[…]` | 卡上的昵称 |

### card add

```sh
esimble card add 'LPA:1$<SM-DP+地址>$<MatchingID>' [--nickname 名字] [--cc 确认码]
esimble card add --qr <二维码图片> [--nickname 名字] [--cc 确认码]
```

用运营商给的激活码或二维码安装新号码，流程遵循 GSMA SGP.22。

| 参数 | 说明 |
|---|---|
| `code` | 激活码，格式 `LPA:1$smdp$matchingId[$oid[$ccFlag]]`。注意用单引号包起来，避免 shell 展开 `$` |
| `--qr` | 二维码图片路径，需要先装 `opencv-python-headless` |
| `--nickname` | 装好后设置卡上的昵称，同时写入数据库作为显示名 |
| `--cc` | 确认码。运营商要求时必须提供，否则会取消会话并报错 |

行为：
- 卡上已有相同 ICCID 时，自动取消会话，不会重复安装；
- 新号码装好后默认是停用状态，需要再运行 `card enable`；
- 安装结果会自动回报给 SM-DP+；
- 失败时会尽量取消会话（同时通知卡和服务器），避免卡上留下半个会话。

输出示例：

```
installed 89852342022498429025
   89852342022498429025   disabled  CMLINK / CMI_GDS
   ...
```

### card enable / card disable

```sh
esimble card enable  <ICCID>
esimble card disable <ICCID>
```

启用或停用一个号码。

- 两者都会请求宿主设备刷新 SIM（refreshFlag），这样新状态才会真正生效。
- 启用一个号码时，卡会自动停用原来启用的号码。
- 返回值：0 表示成功，2 表示"已经是这个状态"，程序也当作成功处理。其他值会报错。

宿主设备的反应（实测）：

| 宿主 | 反应 |
|---|---|
| 安卓手机 | 约 8 秒完成刷新并注网 |
| 随身 WiFi | 约 15 秒识别到新卡，但需要重启设备才能正常注网和收短信，见 03 文档 |
| 停用后没有启用的号码 | 宿主看到的是卡的备用 SIM（ICCID `8911…`，PLMN 111/11），无服务 |

### card nickname

```sh
esimble card nickname <ICCID> <昵称>
```

修改卡上的昵称，UTF-8 编码，支持中文，长度上限 64 字节。

### card delete

```sh
esimble card delete <ICCID> [-y]
```

从卡上**永久删除**这个号码，不可撤销。

- 默认会二次确认，加 `-y` 跳过确认；
- 启用中的号码不能删，要先停用，或者切换到别的号码；
- 删除后数据库里的记录会标记为 `removed`，但不会删除这条记录。

## mifi：随身 WiFi

所有 `mifi` 命令都会在需要时用配置里的密码自动登录。

### mifi status

```sh
esimble mifi status
```

输出设备状态（JSON）。常用字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `loginfo` | 是否已登录 | `ok` |
| `network_type` | 网络制式；`No Service` / `Limited Service` 表示没注上网络 | `LTE` |
| `network_provider` | 当前网络 | `China Unicom` |
| `signalbar` | 信号格数（0～5） | `4` |
| `ppp_status` | 数据连接状态 | `ppp_connected` |
| `sim_current_type` | 当前用的卡槽：`sim` 为外插卡，`esim` / `esim2` 为内置卡 | `sim` |
| `ziccid` | 当前 SIM 的 ICCID，用来判断启用的是哪个号码 | `89852350…` |
| `sim_imsi` | IMSI | `45400…` |
| `msisdn` | 号码（卡里有写才有） | `+1502…` |
| `sms_unread_num` | 未读短信数 | `1` |

### mifi inbox

```sh
esimble mifi inbox [--store 1|0] [--direction in|out|all] [--limit N]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--store` | `1` | `1` 是设备存储（这台设备默认存在这里），`0` 是 SIM 卡存储 |
| `--direction` | `all` | 只看收到的（`in`）、发出的（`out`），或者全部 |
| `--limit` | `50` | 最多输出多少条，按 id 从新到旧 |

每条短信的字段：

| 字段 | 含义 |
|---|---|
| `mifi_id` | 设备上的短信编号，越大越新 |
| `peer` | 对方号码（收到的短信是发件人，发出的短信是收件人） |
| `body` | 已解码的正文 |
| `sms_time` | 设备记录的时间，格式 `yy,MM,dd,HH,mm,ss,时区`。时区是以 15 分钟为单位的偏移：`+32` 表示 +8 小时，`+0` 表示 UTC |
| `tag` | 设备原始标记 |
| `direction` | 按 tag 判断的方向，见下表 |
| `status` | 按 tag 判断的状态，见下表 |
| `store` | 来自哪个存储 |

tag 和方向、状态的对应关系：

| tag | direction | status |
|---|---|---|
| 0 | `in` | `read` |
| 1 | `in` | `unread` |
| 2 | `out` | `sent` |
| 3 | `out` | `failed` |
| 4 | `draft` | `draft` |

读收件箱不会把短信标记为已读，也不会删除。

输出示例（节选）：

```json
[
  {
    "mifi_id": "6",
    "peer": "+86166****4952",
    "body": "……验证码：520cc……",
    "sms_time": "26,11,07,04,54,02,+0",
    "tag": "1",
    "direction": "in",
    "status": "unread",
    "store": 1
  }
]
```

### mifi send

```sh
esimble mifi send <号码> <内容>
```

发送一条短信。

- **号码：** 5～15 位数字，可以带 `+`。建议用国际格式。
- **内容：** 1～70 个 UTF-16 单元，只发单条，不拼长短信，避免多段计费。
- **编码：** 程序按网页端的规则自动选择 GSM7 或 UNICODE。
- **发送前检查：** 无服务、受限服务、正在搜网时拒绝发送。
- **只发一次：** 不会自动重发。

输出字段：

| 字段 | 含义 |
|---|---|
| `outcome` | 发送结果，见下表 |
| `encoding` | `GSM7_default` 或 `UNICODE` |
| `utf16_units` | 内容长度（UTF-16 单元数） |
| `responses` | 原始响应记录 |

`outcome` 的取值：

| 值 | 含义 |
|---|---|
| `accepted` | 基带后端已接受。不代表对方手机已收到 |
| `failed` | 设备报告发送失败（状态 2） |
| `pending` | 60 秒内没有得到最终状态 |
| `rejected` | 设备没有受理这条发送请求 |

> 设备会保留上一次发送的最终状态。程序发送前会先记下这个状态，只认本次的变化，避免把上一次的结果当成这次的。

### mifi sms-ready

```sh
esimble mifi sms-ready
```

查询短信模块的初始化状态。

| 输出 | 含义 |
|---|---|
| `ready` | 状态 3：短信模块正常 |
| `failed (reboot the MiFi)` | 状态 2：初始化失败。这种状态下收件箱不会收到新短信，要运行 `mifi reboot` |
| `initialising (…)` | 正在初始化 |

### mifi wifi

```sh
esimble mifi wifi status|on|off
```

查询、打开或关闭随身 WiFi 的 WiFi 热点。USB 连接不受影响。输出示例：`{"wifiEnabled": "0", "SSID1": "Youmao_29E143"}`。

### mifi reboot

```sh
esimble mifi reboot [-y]
```

重启随身 WiFi，默认会二次确认。

- 重启期间断网，原来的会话失效，程序之后会自动重新登录；
- 实测 5 分钟内能恢复注网，短信模块恢复为 ready；
- 用蓝牙切换号码后，必须做这一步，见 03 文档。

### mifi at

```sh
esimble mifi at '<AT 指令>'
```

通过随身 WiFi 的 AT 桥接执行一条 AT 指令，输出原始响应。

建议只用查询类指令：

| 指令 | 用途 |
|---|---|
| `AT+CEREG?` | 4G 注册状态，第二个数：1 本地、5 漫游、2 搜索中 |
| `AT+CREG?` | 2G/3G 注册状态 |
| `AT+CSQ` | 信号强度；`99,99` 表示测不到信号 |
| `AT+COPS?` | 当前选网 |
| `AT+CPIN?` | SIM 状态 |
| `AT+CIMI` | IMSI |
| `AT+CSCA?` | 短信中心号码 |
| `AT+CNMI?` | 新短信上报方式 |
| `AT+CPMS?` | 短信存储 |

`AT+CFUN=0` 和 `AT+CFUN=1` 可以重启射频，这个操作不写入配置。

**会修改设备配置的 AT 指令（例如 `AT+ZMODE`、`AT+ZSET`）要谨慎使用。**
