# 05 数据存储

默认存在项目目录下。可以用环境变量 `ESIMBLE_DATA` 改数据目录，用 `ESIMBLE_LOGS` 改日志目录。

| 路径 | 内容 | 是否敏感 |
|---|---|---|
| `data/config.json` | 配置，见 01 文档 | 是。含随身 WiFi 管理密码，文件权限 600 |
| `data/esimble.db` | SQLite 数据库（WAL 模式，旁边会有 `-wal`、`-shm` 文件） | 是。含 ICCID、号码、短信内容 |
| `logs/esimble.log` | 运行日志，持续追加 | `-v` 模式下会记录 APDU 和 ICCID |

`.gitignore` 已经排除了 `data/`、`logs/`、`.venv/`。

## 表结构

### profiles：号码

每个号码一行，主键是 ICCID。`card list`、`card add`、`card delete` 会自动同步卡上的字段，平台字段由用户自己维护。

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `iccid` | TEXT PK | 卡 | 号码的卡号 |
| `label` | TEXT | 平台 | 显示名。第一次同步时取卡上的昵称或配置名 |
| `msisdn` | TEXT | 平台 | 手机号。卡上的配置不带号码，需要手动填写，或者从 `mifi status` 读出来再写入 |
| `notes` / `tags` | TEXT | 平台 | 备注、标签 |
| `poll_enabled` / `priority` | INTEGER | 平台 | 平台自定义的启用标记和排序权重。`profiles()` 按 `priority` 从大到小排序 |
| `card_provider` / `card_name` / `card_nickname` | TEXT | 卡 | 运营商、配置名、卡上昵称 |
| `card_state` | TEXT | 卡 | `enabled` / `disabled` / `removed` |
| `profile_class` | TEXT | 卡 | `operational` / `test` / `provisioning` |
| `on_card` | INTEGER | 卡 | 1 表示还在卡上，0 表示已删除（保留记录） |
| `imsi` | TEXT | 平台 | 可从 `mifi status` 读到后写入 |
| `last_active_at`、`last_switch_error`、`last_switch_error_at` | — | 平台 | 平台自己记录 |
| `created_at` / `updated_at` | TEXT | 自动 | 本地时区，ISO 8601 格式 |

### messages：短信

| 字段 | 说明 |
|---|---|
| `id` | 自增主键 |
| `iccid` / `msisdn` | 短信属于哪个号码 |
| `direction` | `in` 或 `out` |
| `peer` | 对方号码 |
| `body` | 正文 |
| `sms_time` | 设备记录的时间（原始格式） |
| `received_at` | 写入数据库的时间 |
| `status` | 发送状态：`pending` / `accepted` / `failed` |
| `via` | 发送来源 |
| `mifi_id` / `mifi_tag` | 随身 WiFi 上的原始编号和标记 |
| `dedup_key` | 去重键，必须唯一。重复插入会被忽略 |

> 命令行的 `mifi inbox` 只读设备，不写这张表。要存短信，用 `Database.add_message()`，示例见 04 文档。

### settings：键值设置

两列：`key`、`value`（JSON）。通过 `get_setting` / `set_setting` 读写。

### events：事件日志

| 字段 | 说明 |
|---|---|
| `ts` | 时间 |
| `level` | `info` / `warning` / `error` |
| `kind` | 事件类别，例如 `card` |
| `message` | 内容 |

装卡、删卡会自动写入一条。最多保留最近 2000 条。

## 备份与清理

```sh
sqlite3 data/esimble.db ".backup data/esimble-backup.db"     # 在线备份
rm -f data/esimble.db*                                        # 清空数据库；下次 card list 时重建号码表
```

配置文件和数据库里有敏感信息，备份和分享时要注意。
