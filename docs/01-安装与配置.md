# 01 安装与配置

## 1. 环境要求

- **系统：** macOS，需要 CoreBluetooth。Linux 理论上可以用 bleak 的 BlueZ 后端，但没有测试过。
- **Python：** 3.10 或以上。开发和实测用的是 3.13。
- **网络：** 能访问运营商的 SM-DP+（装卡时需要）；能通过 USB 网卡访问随身 WiFi 的 `192.168.0.1`。

## 2. 安装

```sh
cd ~/CursorProject/esim-ble
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

也可以按包的方式安装，装好后会多出一个 `esimble` 命令：

```sh
.venv/bin/pip install -e '.[qr]'
.venv/bin/esimble --help
```

依赖：

| 包 | 用途 | 是否必需 |
|---|---|---|
| `bleak` | macOS 蓝牙（CoreBluetooth） | 必需 |
| `cryptography` | 蓝牙登录用的 3DES | 必需 |
| `opencv-python-headless` | `card add --qr` 读二维码图片 | 可选 |

随身 WiFi 客户端只用 Python 标准库。

## 3. 系统权限

**蓝牙权限：** 第一次运行 `card` 相关命令时，macOS 会请求蓝牙权限。权限给的是运行命令的终端程序（Terminal、iTerm、Cursor、VS Code 等），不是 Python 本身。

如果没有弹窗，或者之前点了拒绝：
1. 打开"系统设置 → 隐私与安全性 → 蓝牙"，打开对应终端的开关；
2. 重新打开终端。

没有权限时，bleak 会报蓝牙不可用（例如 `Bluetooth is unsupported`），或者扫描不到设备。

**随身 WiFi 的 USB 网卡：** 随身 WiFi 插上后，macOS 会出现一个新网卡（实测为 `en10`），自动获得 `192.168.0.100` 这样的地址。可以这样检查：

```sh
ifconfig | grep -B4 "inet 192.168.0"
ping -c1 192.168.0.1
```

## 4. 配置

配置保存在 `data/config.json`，文件权限 600。用 `config` 命令修改：

```sh
.venv/bin/python -m esimble config                         # 显示当前配置（不显示密码）
.venv/bin/python -m esimble config --mifi-password         # 交互输入随身 WiFi 管理密码
.venv/bin/python -m esimble config --mifi-host 192.168.0.1
.venv/bin/python -m esimble config --ble-device 9eSIM000000
.venv/bin/python -m esimble config --ble-password          # 只有改过卡的管理密码才需要
.venv/bin/python -m esimble config --secure-tls            # 装卡时用系统证书库校验 SM-DP+
```

配置项：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `ble_device` | `9eSIM000000` | 卡的蓝牙广播名，必须完全一致 |
| `ble_password` | 空 | 卡的管理密码；为空时用设备默认密码（蓝牙名后 6 位倒序） |
| `insecure_tls` | `true` | 装卡时是否跳过 SM-DP+ 的 TLS 证书校验，见第 5 节 |
| `mifi_host` | `192.168.0.1` | 随身 WiFi 管理地址 |
| `mifi_password` | 空 | 随身 WiFi 网页管理密码（贴在设备上或说明书里的管理密码） |

其他配置方式：
- **改数据目录：** 环境变量 `ESIMBLE_DATA` 改配置和数据库所在目录，`ESIMBLE_LOGS` 改日志目录；
- **改配置文件：** 也可以直接编辑 `data/config.json`，未知字段会被忽略。

关于随身 WiFi 登录：
- 设备会按来源 IP 记住登录状态，所以没配密码时，偶尔也能读到数据；
- 设备重启后会话失效。没配密码时，程序会报 `MiFi admin password not configured`。

## 5. SM-DP+ 的 TLS 说明

装卡时要通过 HTTPS 连接运营商的 SM-DP+。SM-DP+ 的服务器证书由 GSMA 的 RSP CI 根证书签发（实测 `consumer.rsp.world` 的签发者是 "GSM Association - RSP2 Root CI1"），这个根证书不在系统证书库里，所以用系统证书库校验会失败。

**默认跳过 TLS 校验（`insecure_tls = true`）。** 这和 lpac、NekokoLPA 上游的做法一致。

跳过 TLS 校验的影响：
- **配置包不会被伪造：** 下发的配置包会经过卡的 eUICC 校验。eUICC 用 CI 公钥验证 SM-DP+ 的证书链和签名，验证不过会拒绝安装。
- **HTTPS 通道本身不受保护：** 理论上中间人可以看到或篡改传输内容，比如激活码。在不可信网络上装卡要注意这一点。

如果要严格校验：
1. 准备 GSMA CI 根证书的 PEM 文件；
2. 运行 `config --secure-tls`；
3. 装卡时设置环境变量 `ESIMBLE_CA_FILE` 指向这个文件。

```sh
ESIMBLE_CA_FILE=/path/to/gsma-ci.pem .venv/bin/python -m esimble card add 'LPA:1$...'
```

## 6. 第一次运行检查

```sh
.venv/bin/python -m unittest discover tests      # 应显示 OK（18 个测试）
.venv/bin/python -m esimble card list            # 应列出 EID 和号码
.venv/bin/python -m esimble mifi status          # 应显示 loginfo: ok 和网络状态
```
