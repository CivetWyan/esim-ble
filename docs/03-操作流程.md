# 03 操作流程

下面的命令都省略了前缀 `.venv/bin/python -m`，实际运行时写成 `.venv/bin/python -m esimble ...`。

## 0. 每次开始前

1. 退出其他连着这张卡的蓝牙客户端（NekokoLPA、9eSIM Mac App、手机上的 9eSIM App 等）。卡同一时间只接受一条蓝牙连接；被占用时不会广播，`card` 命令会报 `BLE device '9eSIM000000' not found`。
2. 卡要插在宿主设备（随身 WiFi 或手机）的 SIM 卡槽里，靠宿主供电。Mac 离卡尽量近，实测 RSSI 约 -84 dBm 仍然可以正常连接。
3. 不要同时运行多个 `esimble` 进程去操作卡。

## 1. 首次接入随身 WiFi

1. 9eSIM 卡插进随身 WiFi 的外插卡槽，随身 WiFi 用 USB 接 Mac。
2. 确认网络通：`ping -c1 192.168.0.1`。
3. 配置管理密码：`esimble config --mifi-password`。
4. 检查状态：`esimble mifi status`，应看到 `loginfo: ok`，`sim_current_type` 为 `sim`（外插卡）。

这台随身 WiFi 之前已经做过一次性设置，这些设置会一直保留，不用重做：
- 外插卡已解锁（`lock_network_status = unlock`）；
- 默认用外插卡（`sim_switch = 0`）。

如果换了一台同型号的新设备，`sim_current_type` 显示 `esim`/`esim2`，或者外插卡被锁，需要先解锁。这台设备当时的解锁过程记录在 `analysis/mifi-sms/README.md`，涉及临时打开调试模式和网络解锁，会改设备配置，操作前要确认已获得授权。

可选：关闭 WiFi 热点，只用 USB：`esimble mifi wifi off`。

## 2. 安装新号码

1. 先看卡上现有的号码：`card list`。
2. 安装：

   ```sh
   card add 'LPA:1$consumer.rsp.world$XXXXXXXX' --nickname 我的号
   # 或者用二维码图片：
   card add --qr ~/Downloads/qr.jpg --nickname 我的号
   ```

3. 安装大约要 40 秒（30 KB 的配置包分 36 段写入）。日志会依次显示：
   - `initiateAuthentication`
   - `AuthenticateServer`
   - `authenticateClient`
   - `profile offered: provider=… iccid=…`
   - `PrepareDownload`
   - `getBoundProfilePackage`
   - `segment i/n`
   - `install notification delivered`
4. 装好后号码是停用状态，`card list` 里能看到。
5. 要用这个号码，按第 3 节启用。

注意：
- **不要中途断开：** 写入过程中不要中断蓝牙，也不要把卡拔出来。
- **中途失败时：** 先运行 `card list` 看号码是否已经装上，不要盲目重下。
- **激活码能否重复用：** 同一个激活码能不能装第二次，取决于运营商。实测 CMLink 的激活码在删除后可以再装。

## 3. 切换号码并收短信（卡在随身 WiFi 里）

### 推荐流程

```sh
card list                       # 确认目标号码的 ICCID
card enable <ICCID>             # 约 8 秒
mifi reboot -y                  # 重启随身 WiFi
# 等 1～5 分钟
mifi status                     # 应为 network_type 正常（如 LTE）、ziccid 是目标号码
mifi sms-ready                  # 应为 ready
mifi inbox --direction in       # 查看收到的短信
```

### 为什么要重启（实测，2026-11-07）

| 时间 | 操作 | 随身 WiFi 状态 |
|---|---|---|
| 开机时 | 卡上没有启用的号码 | 看到的是卡的备用 SIM（`8911…`，PLMN 111/11），无服务；短信模块初始化**失败**（状态 2） |
| 12:54:23 | `card enable` Saily | 卡返回 0（成功） |
| 12:54:41 | — | `ziccid` 变成 Saily 的号码，也读到了号码，说明 SIM 刷新成功 |
| 12:54～12:57 | — | 一直无服务。`CEREG 2,2`（正在搜网），`CSQ 99,99`（测不到信号） |
| 12:57:43 | `AT+CFUN=0` → `AT+CFUN=1` | 85 秒后注上联通 4G（漫游），但短信模块**仍然是失败状态**，短信没进收件箱 |
| 13:05:39 | `REBOOT_DEVICE` | 重启 |
| 13:13 前 | — | 4G 已注册，信号 4～5 格，短信模块状态 3（ready）。12:53 发来的短信由网络补发到达 |

结论：
- 这台随身 WiFi 在 SIM 刷新后不会自动重新搜网，也不会重新初始化短信模块；
- 重启整台设备后，它会以新号码开机，一切恢复正常；
- 之前 codex 能收到短信，也是因为设备是在号码已启用的状态下开机的。

### 收短信的特点

- **只有启用中的号码能收短信：** 卡上同一时间只有一个号码在线。
- **离线期间的短信多数会补发：** 发给离线号码的短信，运营商通常会暂存，号码上线后补发。实测：12:53 发出的短信，在随身 WiFi 重启恢复后（13:13 前）收到。暂存多久由运营商决定，不能保证。
- **短信默认存在设备存储：** 读 `mifi inbox` 即可（`--store 1`）。
- **怎么判断短信属于哪个号码：** 收件箱是设备级的，所有号码的短信混在一起，记录里不带"属于哪个号码"的信息。可以根据收到短信时 `mifi status` 的 `ziccid` 来判断。

## 4. 切换号码（卡在安卓手机里）

```sh
card enable <ICCID>
```

手机约 8 秒完成刷新并注网，不需要额外操作。可以用 ADB 确认：

```sh
adb shell getprop gsm.sim.operator.numeric
adb shell dumpsys isub | grep simSlotIndex=1
```

## 5. 停用和删除号码

```sh
card disable <ICCID>            # 停用后没有启用的号码，宿主看到的是备用 SIM，无服务
card delete <ICCID>             # 会二次确认；不可撤销
```

- 启用中的号码不能删，要先停用，或者切到别的号码；
- 删除会回收卡上的空间：实测删除 CMI_GDS 后，剩余空间从 991.11 KB 回到 1047.58 KB；
- 删除后卡上会留一条"删除通知"，等待回报给运营商。本工具只自动处理装卡后的通知，这条通知会一直留在卡上。

## 6. 改名

```sh
card nickname <ICCID> 'CMLink测试'
```

昵称存在卡上，换设备或换工具都能看到。`card list` 显示在方括号里。

## 7. 发短信

```sh
mifi send +8613800000000 'hello'
```

- 发送前确认号码在线：`mifi status` 显示正常网络；
- 号码套餐要包含短信发送。测试卡 Saily 经确认没有开通短信发送，之前 4 次发送都失败了（tag 3）；
- 只发一次，不自动重发；`outcome: accepted` 只代表基带后端接受，不代表对方已收到。
