# 08 接码平台

在 01～07 的卡管理和随身 WiFi 功能之上，加了一个常驻服务：

- 网页后台：管理号卡、看短信、发短信、调设置；
- REST 接口、Python SDK、MCP 服务：让 AI 能"选号 → 等短信 → 读验证码"。

原有的代码和命令（`esimble card …`、`esimble mifi …`）没有改动。平台代码都在 `esimble/platform/` 目录下。

> **平台运行时，不要再用 `esimble card`、`esimble mifi` 命令去操作卡和随身 WiFi。**
> 卡同一时间只接受一条蓝牙连接，随身 WiFi 收件箱里的短信也会被平台入库后删除。手动命令会和平台互相干扰。

## 1. 安装和启动

```sh
cd ~/CursorProject/esim-ble
.venv/bin/pip install -r requirements-platform.txt       # fastapi、uvicorn、mcp
.venv/bin/python -m esimble config --mifi-password        # 如果还没配置过
.venv/bin/python -m esimble.platform serve                # 前台运行，Ctrl+C 停止
```

也可以直接用一键脚本（推荐）：`./start.sh`、`./stop.sh`、`./restart.sh`，状态用 `scripts/platform.sh status` 查看。脚本说明：
- **启动：** 首次运行会自动创建 `.venv`、安装依赖；平台在后台运行，PID 写在 `data/platform.pid`；30 秒内服务没响应，就打印日志并报失败。
- **重复启动：** 平台已经在运行时，只打印登录链接，不会再启动一份。
- **关闭：** 先正常结束，15 秒还没退出就强制结束。能识别没有 PID 文件的旧进程，只关闭从本目录启动的那一份。
- **端口被占用：** 如果 8787 端口被其他程序占用，会直接报错，不会启动。

用 `serve` 命令前台运行时，启动后终端会打印：

```
  管理后台: http://127.0.0.1:8787/login?token=…
  API 文档: http://127.0.0.1:8787/api/docs
```

用浏览器打开带令牌的那条链接，登录状态保持 30 天。忘了链接可以这样找回：

```sh
.venv/bin/python -m esimble.platform token
```

如果要在后台长期运行：

```sh
nohup .venv/bin/python -m esimble.platform serve >> logs/platform-stdout.log 2>&1 &
```

## 2. 工作方式

### 2.1 只有一个号在线

9eSIM 卡同一时间只能启用一个号码，所以平台每次只让一个号在线。

**切号流程（全自动）：**
1. 把当前收件箱收干净；
2. 通过蓝牙启用目标号码；
3. 重启随身 WiFi；
4. 等到随身 WiFi 报告的 ICCID 是目标号码、网络正常、短信模块就绪。

2026-11-07 实测，Cellfie 和 Saily 各切了一次，都在 35～40 秒内完成。超过"切号超时"（默认 600 秒）就算失败。失败的号码 30 分钟内不再参与轮询，但按需等码时会重新尝试。

### 2.2 调度规则：常驻号 + 按需收码（默认）

- **常驻号：** 在"系统设置"里指定（当前是 Saily / WEBBING），或者在号卡列表里点"设为常驻"。没有收码会话时，平台始终让常驻号在线，所以它的短信实时到达、不会丢。
- **收码：** 要用其他号码时，在"收码"页选中号码，点"开始收码"；或者由 AI 调 `prepare_number` / `wait_for_sms`。平台立即切到那个号，页面实时显示切换进度：收取当前短信 → 蓝牙启用 → 重启随身 WiFi → 识别号码 → 注册网络 → 短信就绪 → 在线。**显示"在线"之后再让对方发短信。**
- **收码会话：** 默认保持"收码保持"秒（600 秒）。可以"延长 10 分钟"或"结束"。结束或到期后，自动切回常驻号。
- **多个收码请求：** 先到先服务。当前在线号码上有请求时，优先满足它。
- **自动轮询（不推荐，默认关闭）：** 所有勾选的号码轮流上线，每个号停留"轮询停留"秒。打开后，离线的号码收不到实时短信。2026-11-07 实测，有一条发给离线 Saily 的短信，运营商没有补发。

**离线期间的短信：** 号码不在线时，发给它的短信由运营商暂存，等号码上线后再补发，但补发时间和是否补发都不确定。实测有补发到的，也有到现在都没到的。

### 2.3 短信入库和归属

- 每隔"收取间隔"秒（默认 5）读一次随身 WiFi 收件箱，写进 `data/esimble.db` 的 `messages` 表。重复的短信会去重。
- **归属：** 短信归到当时随身 WiFi 报告的号码（`ziccid`）下。每次切号前会先把收件箱收干净，所以不同号码的短信不会混在一起。
- **`attribution` 字段：**

  | 取值 | 含义 |
  |---|---|
  | `active` | 正常归属 |
  | `startup` | 平台启动时设备里已有的旧短信，按启动时在线的号码推断，后台显示"归属待确认" |
  | `unknown` | 当时在线的 SIM 不是平台管理的号码 |
  | `sent` | 平台发出的短信 |

- **入库后删除：** 随身 WiFi 只能存 20 条短信。默认开启这个选项，短信写进数据库后，就从设备上删除，包括收到的和发送失败的；草稿保留。可以在设置里关闭。
- **验证码：** 收到短信时自动提取。先找"验证码 / code / OTP"等关键词后面的 3～10 位字母数字（例如 `520cc`），找不到再找独立的 4～8 位数字，日期和时间会排除。提取结果存在 `code` 字段。
- **号码自动补全：** 号码上线时，如果随身 WiFi 能读到手机号（`msisdn`），而平台里还没填，会自动补上。实测 Saily 能读到，Cellfie 读不到，要在后台手动填写。

## 3. 网页后台

左侧是菜单，右侧是对应页面：

| 菜单 | 功能 |
|---|---|
| 概览 | 当前在线号码、网络、运行阶段、设备短信存储；号卡速览（每个号有"收码"按钮）；最近短信 |
| 收码 | 左边选号码，右边是收码面板：离线号码显示"开始收码"；切换中显示分步进度和用时；在线后提示"现在可以发短信到 …"；下方实时显示这个号收到的短信，最新验证码会放大显示，点击就能复制 |
| 号卡管理 | 新增（激活码或二维码）、编辑（名称、手机号、标签、备注、卡上昵称）、设为常驻、删除（要输入 ICCID 后 4 位确认，在线号码不能删）、从卡上刷新 |
| 短信记录 | 按号码、方向筛选，可以搜索，新短信自动出现，可以加载更多 |
| 发送短信 | 只能从在线号码发送 |
| 系统设置 | 常驻号、收码保持、切号超时、自动轮询、收取间隔、入库后删除、API 发短信 |
| 事件日志 | 切号、装卡、删卡、设置修改等记录 |
| 接入 API / MCP | 接入方法和示例 |

页面每 2.5 秒刷新一次。新短信会在右上角弹出提示，左侧"短信记录"菜单上显示未读数。

## 4. REST 接口

- **基地址：** `http://127.0.0.1:8787/api/v1`
- **鉴权：** 请求头 `Authorization: Bearer <token>`，可选加 `X-Client: rest|sdk|mcp` 标记调用来源。
- **完整文档：** `/api/docs`（OpenAPI）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/status` | 运行状态 |
| GET | `/numbers` | 号码列表（`?include_removed=true` 会包含已删除的） |
| GET | `/numbers/{key}` | `key` 可以是 ICCID、手机号或显示名称 |
| PATCH | `/numbers/{key}` | 修改 `label`、`msisdn`、`notes`、`tags`、`poll_enabled`、`priority`、`card_nickname`（`card_nickname` 会通过蓝牙写入卡） |
| POST | `/numbers` | 装新号（表单字段：`activation_code` 或文件 `qr`，以及 `nickname`、`confirmation_code`、`label`、`msisdn`、`notes`、`tags`） |
| DELETE | `/numbers/{iccid}?confirm={iccid}` | 从卡上删除 |
| POST | `/card/refresh` | 用蓝牙重读卡 |
| POST | `/numbers/{key}/prepare` | 开始让号码上线，返回 `cursor`（当前最大短信 id）、`online`、`eta_seconds` |
| POST | `/numbers/{key}/receive` | 开始收码会话（切换并保持；别名 `/switch`；MCP 不能调用），返回 `hold_id`、`cursor` |
| POST | `/holds/{id}/extend?seconds=600` | 延长收码会话 |
| DELETE | `/holds/{id}` | 结束收码会话（之后回到常驻号） |
| POST | `/wait` | 长轮询等待新短信：`{"number", "since_id", "timeout", "sender", "contains"}`。返回 `status` 为 `received`、`pending` 或 `switch_failed`，收到时附带 `code` |
| GET | `/messages` | 短信列表：`number`、`direction`、`since_id`、`before_id`、`limit`、`sender`、`contains` |
| GET | `/messages/latest-code` | 某个号码最近一次收到的验证码 |
| POST | `/send` | 发短信：`{"number", "to", "text"}`。通过令牌调用时，需要在设置里打开"API 发短信" |
| GET | `/events` | 事件日志 |

后台网页用的是 cookie 登录，并且要带 `X-Requested-With: esim-admin` 请求头。设置修改和删除短信只能在后台网页上操作。

## 5. Python SDK

只用标准库，可以在任何 Python 环境里直接用，复制 `esimble/platform/sdk.py` 一个文件即可。

```python
from esimble.platform.sdk import SmsPlatform

p = SmsPlatform()            # 默认读取本项目 data/platform.json 里的端口和令牌
# 或者 SmsPlatform("http://127.0.0.1:8787", "<token>")，也可以用环境变量 ESIM_PLATFORM_URL / ESIM_PLATFORM_TOKEN

n = p.prepare("WEBBING")                    # 开始让号码上线，拿到 cursor
# …… 让网站往这个号发验证码 ……
r = p.wait_for_code("WEBBING", since_id=n["cursor"], timeout=600)
print(r["status"], r.get("code"))
```

其他方法：`status()`、`numbers()`、`number(key)`、`messages(...)`、`latest_code(...)`、`wait(...)`、`update_number(key, **fields)`、`switch(key)`、`refresh_card()`、`delete_number(iccid)`、`send(number, to, text)`。

## 6. MCP 服务

MCP 服务走 stdio，本身不碰硬件，只通过 REST 调用正在运行的平台。所以要先启动 `serve`。

生成各个客户端的配置：

```sh
.venv/bin/python -m esimble.platform mcp-config
```

输出里有三段，分别对应：
- Claude Code 的 `claude mcp add …` 命令；
- Cursor 和 Claude Desktop 的 `mcp.json`；
- Codex 的 `config.toml`。Codex 默认的工具超时可能比等码时间短，配置里已经设了 `tool_timeout_sec = 120`。

**工具：**

| 工具 | 说明 |
|---|---|
| `get_status` | 当前在线号码、切号阶段、等待请求 |
| `list_numbers` | 号码列表 |
| `prepare_number(number)` | 开始让号码上线，返回 `cursor` |
| `wait_for_sms(number, since_id, timeout_seconds≤50, sender_contains, body_contains)` | 等新短信。返回 `pending` 时再调一次 |
| `get_latest_code(number, …)` | 直接取最近的验证码，不等待 |
| `list_messages(...)` | 查已存的短信 |
| `send_sms(number, to, text)` | **只有**在设置里打开"API 发短信"后才会出现，改完要重启 MCP 客户端 |

**典型流程：** `list_numbers` → `prepare_number` → 让网站发验证码 → 反复调用 `wait_for_sms(since_id=cursor)`，直到 `received`。

**自检：** `.venv/bin/python scripts/mcp_smoke.py [号码]`。它会像 AI 客户端一样，通过 stdio 拉起 MCP 服务，并调用只读工具。

> 短信正文来自第三方，MCP 的 `instructions` 已经提醒 AI 只把正文当数据，不当指令。

## 7. 安全

- **只监听本机：** 服务只监听 `127.0.0.1`，并且只接受 Host 为 `127.0.0.1` 或 `localhost` 的请求，防止 DNS 重绑定。
- **令牌：** 存在 `data/platform.json`（权限 600）。`python -m esimble.platform token --rotate` 可以换新令牌，换完要重启服务，并更新各 MCP 配置。
- **后台 cookie：** HttpOnly + SameSite=Strict。写操作还要带自定义请求头，用来防 CSRF。

## 8. 配置文件 `data/platform.json`

| 键 | 默认值 | 说明 |
|---|---|---|
| `host` / `port` | `127.0.0.1` / `8787` | 监听地址 |
| `api_token` | 随机生成 | API 令牌 |
| `home_iccid` | 空 | 常驻号的 ICCID |
| `rotation_enabled` | `false` | 自动轮询（不推荐） |
| `dwell_seconds` | 600 | 轮询时每个号停留多久 |
| `poll_seconds` | 5 | 收件箱读取间隔 |
| `switch_timeout_seconds` | 600 | 切号超时 |
| `wait_hold_seconds` | 600 | 收码会话或 AI 等码时，号码保持在线多久 |
| `switch_retry_after_seconds` | 1800 | 切换失败后，多久内不再参与轮询 |
| `delete_after_store` | `true` | 入库后从随身 WiFi 删除 |
| `api_allow_send` | `false` | 是否允许 REST、SDK、MCP 发短信 |

除了 `host`、`port`、`api_token`，其他键都可以在后台"设置"里改，改完立即生效。

## 9. 日志和排查

- **日志：** `logs/platform.log`（滚动保存，单个 5 MB，保留 3 份）；前台运行时，终端也会输出。
- **常见现象：**

| 现象 | 处理 |
|---|---|
| 阶段一直是"随身WiFi不可达" | 检查 USB 连接，`ping 192.168.0.1` |
| 切号失败 `BLE device … not found` | 退出其他蓝牙客户端（NekokoLPA、9eSIM App 等）。卡同一时间只接受一条连接 |
| 切号超时，`sms_ready` 一直是 2 | 短信模块初始化失败，见 06 故障排查。平台会把这个号冷却 30 分钟，然后换下一个 |
| 后台提示"device busy" | 正在切号或装卡，等一会儿再操作 |

## 11. 设备管理：新卡、新随身 WiFi、多组设备

**设备组** = 一张 9eSIM 蓝牙卡 + 插着它的一台随身 WiFi。每组同时有一个号码在线，几组就有几个号同时实时收短信。各组独立调度，各自有常驻号和自动轮询开关。蓝牙操作在所有组之间串行执行（Mac 同一时间只连一张卡）。

旧版的单设备配置会在首次启动时自动迁移成"设备组 1"，原有号码都归到这一组。

### 11.1 接入一张全新的 9eSIM 卡

1. 卡插进随身 WiFi（或手机），保证供电；退出手机、电脑上的 9eSIM、NekokoLPA 等 App，否则卡不广播。
2. 打开后台"设备管理"，在"附近的 9eSIM 卡"点**扫描**（约 6 秒）。列表显示蓝牙名、信号强度，以及是否已属于某个设备组。
3. 点"添加设备组"，在"① 9eSIM 蓝牙卡"里点**扫描**，再点"选这张"；然后点**测试连接**，成功会显示 EID 尾号、号码数量和剩余空间。
4. **蓝牙密码：** 留空就用默认密码，默认密码由卡名推算；如果在 9eSIM App 里改过密码，就填改过的那个。

### 11.2 接入一台新的随身 WiFi

1. 随身 WiFi 用 USB 接 Mac，等它开机完成（约 1 分钟）。
2. 在"② 随身 WiFi"里点**扫描**：平台会检查 Mac 上的每个网卡，找出能响应管理接口的设备地址；然后点"选这台"。
3. **后台密码**默认是 `admin`。点**测试登录**，会显示型号、IMEI 尾号和网络。IMEI 会被记下来，用来在地址改变后认出同一台设备。

### 11.3 多台随身 WiFi（地址冲突）

同型号的随身 WiFi 出厂地址都是 `192.168.0.1`。两台同时插上时，Mac 只能访问到其中一台，扫描结果会显示"地址冲突"。

处理步骤：
1. 拔掉其他随身 WiFi，**只插新的那台**；
2. 在向导里选它。如果地址已被其他设备组使用，或者扫描到冲突，会出现"改地址"框，并自动推荐一个空闲网段（如 `192.168.1.1`）；
3. 点**改地址**：平台调用设备的局域网设置接口，设备会自动重启（实测说明见下）。平台在新地址上等到它恢复，再核对 IMEI，确认是同一台；
4. 保存设备组后，再把其他随身 WiFi 插回来。

限制：
- 正在运行的设备组用的随身 WiFi 不能改地址，要先停用这一组；
- 新地址必须是以 `.1` 结尾的私有 IPv4 地址。

### 11.4 设备组的其他操作

- **编辑：** 改名称、蓝牙名和密码、管理地址和密码、常驻号、自动轮询。改设备参数会重启这一组的调度；只改名称、常驻号、轮询，立即生效，不重启。
- **停用 / 启用：** 停用后这组不再收短信，卡和号码记录保留。
- **移除：** 平台不再管理这组设备，卡上的号码不会被删除。最后一个设备组不能移除。
- **装新号：** 有多个设备组时，"新增号卡"对话框里要选写入哪张卡。

### 11.5 接口

只能从后台网页调用，令牌调用返回 403。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/groups` | 设备组列表和各自的运行状态 |
| POST / PATCH / DELETE | `/groups[/{id}]` | 添加、修改、移除设备组 |
| POST | `/discover/cards` | 扫描附近的 9eSIM 卡 |
| POST | `/discover/cards/test` | 试连一张卡：`{"name", "password"}` |
| GET | `/discover/mifis` | 扫描 USB 随身 WiFi，返回冲突网段和推荐地址 |
| POST | `/discover/mifis/test` | 登录一台随身 WiFi：`{"host", "password"}` |
| POST | `/discover/mifis/relocate` | 改随身 WiFi 的地址：`{"host", "password", "new_host"}` |

另外：`/status` 增加了 `groups` 字段，`/numbers` 每条记录带 `device_id` 和 `group_name`。号码相关的接口（收码、等码、发短信）会自动路由到号码所在的设备组。MCP 不需要任何修改。

## 12. MCP 自动启停平台

AI 工具（Claude Code、Cursor、Codex）通过 MCP 使用平台时，不需要先手动启动平台。

- **自动启动：** 打开 AI 工具时不会启动平台。AI **第一次调用工具**时，如果发现平台没在运行，MCP 会调用 `scripts/platform.sh start` 把它拉起来，然后等它读完卡再返回结果，首次调用大约多花 10～20 秒。多个 AI 工具同时触发启动时，有文件锁保证只启动一份。
- **自动关闭：** 每个 MCP 服务进程在 `data/mcp-leases/` 里登记一个文件，进程被强制结束的情况也能识别。平台每 10 秒检查一次：**所有** MCP 客户端都断开、并且已经过了"MCP 自动关闭"时间（默认 120 秒，在"系统设置"里改）之后：
  1. 结束 AI 发起的等码请求；
  2. 等每个设备组切回常驻号；
  3. 自动关闭平台，并记一条事件。

  有以下情况时会推迟关闭：后台还有你手动开的收码会话，或者某组正在切号。
- **只关 MCP 启动的平台：** 自动启动时会写入 `data/platform.autostart`。用 `./start.sh` 或双击启动的平台不会被自动关闭；MCP 启动的平台运行期间，再执行一次 `./start.sh`，就改为手动常驻。`scripts/platform.sh status` 和后台左下角会显示当前是哪种。
- **关闭期间的短信：** 随身 WiFi 照常接收，存在设备里（最多 20 条）。下次启动时入库，号码没变的话直接归到这个号码下（不再标"归属待确认"）。
- **关闭自动启动：** 在 MCP 配置的 `env` 里加 `ESIM_MCP_AUTOSTART=0`。平台地址不是本机（127.0.0.1）时，也不会自动启动。

实测（2026-11-09）：
- 先关闭平台，再调用 MCP：平台被自动拉起，约 10 秒返回 `online`；
- MCP 退出 120 秒后，平台自动关闭，随身 WiFi 停在常驻号 Saily；
- 平台由 MCP 启动后执行 `./start.sh`：改为手动常驻。
