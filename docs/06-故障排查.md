# 06 故障排查

排查前先加 `-v` 重跑一次，查看完整日志（终端，或 `logs/esimble.log`）。

## 卡管理（蓝牙）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `BLE device '9eSIM000000' not found` | 卡被别的蓝牙客户端占用了，不广播 | 退出 NekokoLPA、9eSIM Mac App、手机上的 9eSIM App 后重试 |
| 同上 | 卡没通电 | 确认卡插在宿主设备里，宿主已开机 |
| 同上 | 距离太远 | Mac 靠近宿主设备 |
| 同上 | 蓝牙名不对 | 用 `config --ble-device` 改成正确的名字 |
| `Bluetooth is unsupported` / 扫描结果为空 | 终端没有蓝牙权限 | 系统设置 → 隐私与安全性 → 蓝牙，打开对应终端，然后重开终端 |
| 同上 | 在沙箱或远程环境里运行 | 改在本机终端运行 |
| `authentication failed: wrong password` | 卡的管理密码被改过 | `config --ble-password` 输入正确密码 |
| `timed out waiting for authentication challenge` | 连接不稳定，或卡正忙 | 稍等后重试；仍然失败就把宿主设备断电重启 |
| `SELECT ISD-R failed (SW=6999)` / `6985` | 卡正在处理启停，宿主设备的 SIM 刷新还没完成 | 程序会自动等 20 秒重试一次；仍然失败就再等 30 秒手动重试。不要连续反复执行启停 |
| `enable returned 1` 或其他非 0 值 | 卡拒绝了操作，比如 ICCID 不对 | 用 `card list` 核对 ICCID |
| `profile is enabled; disable it … first` | 尝试删除启用中的号码 | 先 `card disable`，或者启用别的号码 |

## 装卡

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `CERTIFICATE_VERIFY_FAILED` | 开了 `--secure-tls`，但系统证书库里没有 GSMA CI 根证书 | 设置 `ESIMBLE_CA_FILE`，或者恢复默认设置（见 01 文档第 5 节） |
| `SmdpError: <接口>: Failed subject=… reason=…` | SM-DP+ 拒绝：激活码已经用过、过期或无效 | 联系运营商重新获取激活码 |
| `AuthenticateServer refused by eUICC, error code N` | 卡不接受这个 SM-DP+（证书或 CI 不匹配） | 确认激活码适用于消费级 eSIM（SGP.22） |
| `SM-DP+ requires a confirmation code (--cc)` | 运营商要求确认码 | 加上 `--cc 确认码` |
| `install failed at …: installFailedDueToInsufficientMemoryForProfile` | 卡的空间不够 | 删掉不用的号码 |
| `…IccidAlreadyExistsOnEuicc` / 安装被自动取消 | 卡上已经有这个号码 | 不需要处理 |
| 中途断线报错 | 写入时蓝牙断开 | 先 `card list` 看号码是否已经装上，再决定是否重装 |

## 随身 WiFi

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `MiFi unreachable at http://192.168.0.1` | USB 没连好，或者设备在重启 | 检查 `ping 192.168.0.1` 和 `ifconfig` 里有没有 `192.168.0.x` 地址；重启后要等 1～5 分钟 |
| `MiFi admin password not configured` | 没配密码，而设备的会话已经失效（比如重启过） | `config --mifi-password` |
| `MiFi login failed` | 密码错误 | 重新配置密码。不要反复尝试 |
| `network_type: No Service`，`ziccid` 是 `8911…` | 卡上没有启用的号码，宿主看到的是备用 SIM | `card enable <ICCID>` |
| 切号后 `ziccid` 已经变了，但一直无服务；`AT+CSQ` 为 `99,99` | 随身 WiFi 在 SIM 刷新后没有重新搜网 | `mifi reboot -y`（`AT+CFUN=0/1` 也能恢复注网，但修不好短信模块） |
| 已注网，但 `mifi sms-ready` 显示 `failed` | 短信模块在开机时初始化失败，之后不会自动恢复 | `mifi reboot -y` |
| 已注网、短信模块 ready，但没收到短信 | 网络还没补发；发错了号码；号码不支持接收这类短信 | 等几分钟；用 `mifi status` 核对 `msisdn`；换一个发件号码试试 |
| `mifi send` 的 `outcome: failed` | 套餐没有开通短信发送，或者被运营商拒绝 | 确认套餐包含短信发送；设备不会给出具体原因 |
| `mifi send` 报 `modem has no normal service` | 没注网 | 先恢复注网 |

## 收集诊断信息

遇到问题时，先收集下面这些信息再处理（都是只读命令）：

```sh
.venv/bin/python -m esimble -v card list
.venv/bin/python -m esimble mifi status
.venv/bin/python -m esimble mifi sms-ready
for c in 'AT+CPIN?' 'AT+CFUN?' 'AT+COPS?' 'AT+CREG?' 'AT+CEREG?' 'AT+CSQ' 'AT+CSCA?' 'AT+CNMI?' 'AT+CPMS?'; do
  echo "$c"; .venv/bin/python -m esimble mifi at "$c"
done
tail -200 logs/esimble.log
```

`CEREG` / `CREG` 的第二个数字表示注册状态：

| 值 | 含义 |
|---|---|
| 1 | 已注册（本地网络） |
| 5 | 已注册（漫游） |
| 2 | 未注册，正在搜网 |
| 3 | 注册被拒绝 |
| 0 | 未注册，也没有在搜网 |
